# REVISI 1
## Bagian : 4.2 District

### Ganti bagian:

```text
Digunakan oleh:

- User
- Sub Operator

Alasan dibuat:

Menentukan wilayah kerja Sub Operator dan asal wilayah laporan.
```

### Menjadi:

```text
Digunakan oleh:

- User (Opsional sebagai informasi domisili)
- Sub Operator
- Deceased

Alasan dibuat:

District digunakan sebagai referensi wilayah administratif dalam sistem.

District menjadi dasar penentuan wilayah kerja Sub Operator serta dasar distribusi laporan berdasarkan domisili Almarhum sehingga setiap laporan secara otomatis diteruskan kepada Sub Operator sesuai wilayahnya.
```

---

# REVISI 2
## Bagian : 4.8 Report

### Ganti bagian:

```text
Data yang disimpan meliputi:

- Nomor Laporan
- Pelapor
- Status
- Tanggal Laporan
```

### Menjadi:

```text
Data yang disimpan meliputi:

- Nomor Laporan
- Pelapor
- Status Laporan Saat Ini
- Tanggal Laporan
```

---

### Tambahkan setelah bagian:

```text
Alasan dibuat:

Merupakan inti proses bisnis SIPKP.
```

### Tambahkan:

```text
Entity Report hanya menyimpan informasi utama laporan beserta status terakhirnya.

Seluruh riwayat perubahan status dan proses verifikasi disimpan pada entity Report Verification sebagai audit trail.
```

---

# REVISI 3
## Bagian : 4.9 Deceased

### Ganti bagian:

```text
Data meliputi:

- NIK
- Nama
- Jenis Kelamin
- Tempat Lahir
- Tanggal Lahir
- Alamat
- Tempat Meninggal
- Tanggal Meninggal
```

### Menjadi:

```text
Data meliputi:

- NIK
- Nomor Kartu Keluarga (KK)
- Nama Lengkap
- Jenis Kelamin
- Tempat Lahir
- Tanggal Lahir
- Alamat Lengkap
- Kabupaten/Kota
- Tanggal Meninggal
```

---

### Tambahkan setelah:

```text
Dipisahkan dari Report agar struktur database lebih terorganisir dan sesuai prinsip normalisasi.
```

### Tambahkan:

```text
Data Kabupaten/Kota pada entity Deceased digunakan sebagai dasar penentuan wilayah verifikasi oleh Sub Operator.
```
